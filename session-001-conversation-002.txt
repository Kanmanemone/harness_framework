        1 +# PRD: YouTube Comment Analyzer                               
        2 +                                                              
        3 +## 목표                                                       
        4 +YouTube 영상 URL만 입력하면 댓글을 자동 수집하고 AI로 센티먼트
          + 분석하여, 크리에이터가 시청자 반응을 한눈에 파악할 수 있는 리
          +포트를 생성한다.                                              
        5 +                                                              
        6 +## 사용자                                                     
        7 +YouTube 크리에이터 및 콘텐츠 제작자. 자신의 영상에 대한 시청자
          + 피드백을 빠르게 파악하고 싶은 사람.                          
        8 +                                                              
        9 +## 사전 준비                                                  
       10 +사용자는 다음 두 가지 API 키를 직접 발급받아야 한다:          
       11 +1. **YouTube Data API v3 키**: [Google Cloud Console](https://
          +console.cloud.google.com/)에서 프로젝트 생성 → YouTube Data AP
          +I v3 활성화 → API 키 발급. 일일 무료 할당량 10,000 유닛 (comme
          +ntThreads.list 1회 = 1 유닛).                                 
       12 +2. **Anthropic API 키**: [Anthropic Console](https://console.a
          +nthropic.com/)에서 계정 생성 → API 키 발급. 사용량 기반 과금.

       16 +## 핵심 기능                                                  
       17 +                                                              
       18 +### 기능 1: YouTube URL 입력 및 댓글 수집                     
       19 +YouTube 영상 URL을 입력하면 해당 영상의 댓글을 자동으로 수집한
          +다.                                                           
       20 +                                                              
       21 +**지원하는 URL 형식:**                                        
       22 +- `https://www.youtube.com/watch?v=VIDEO_ID`                  
       23 +- `https://youtu.be/VIDEO_ID`                                 
       24 +- `https://www.youtube.com/embed/VIDEO_ID`                    
       25 +- `https://www.youtube.com/v/VIDEO_ID`                        
       26 +- 위 형식에 추가 쿼리 파라미터(`&t=`, `&list=` 등)가 붙어도 동
          +작                                                            
       27 +                                                              
       28 +**수집 규칙:**                                                
       29 +- 최대 100개 댓글 수집 (YouTube API `maxResults` 상한)        
       30 +- 관련도순(`order=relevance`) 정렬 — 좋아요 많고 답글 많은 의 
          +미 있는 댓글 우선                                             
       31 +- 최상위 댓글만 수집 (대댓글 제외)                            
       32 +- 일반 텍스트(`textFormat=plainText`) 형식으로 가져옴         
       33 +                                                              
       34 +**수용 기준:**                                                
       35 +- 유효한 YouTube URL 입력 시 댓글이 수집되어야 한다           
       36 +- 댓글 수집 중 로딩 상태가 UI에 표시되어야 한다               
       37 +- 수집된 댓글 수가 리포트에 표시되어야 한다                   
       38 +                                                              
       39 +### 기능 2: AI 센티먼트 분석                                  
       40 +수집된 댓글을 Claude AI에 전송하여 센티먼트를 분석한다.       
       41 +                                                              
       42 +**분석 항목:**                                                
       43 +- 전체 요약 (1-2문장)                                         
       44 +- 센티먼트 비율: 긍정/중립/부정 퍼센트 (합계 100%)            
       45 +- 잘하고 있는 점: 최대 5개, 구체적이고 댓글에 근거한 내용     
       46 +- 개선할 점: 최대 5개, 구체적이고 댓글에 근거한 내용          
       47 +- 대표 댓글: 긍정/중립/부정 각 2-3개, 원문 인용               
       48 +                                                              
       49 +**분석 언어:**                                                
       50 +- 댓글이 한국어면 분석도 한국어로, 영어면 영어로. 댓글의 주 언
          +어를 따라간다.                                                
       51 +                                                              
       52 +**수용 기준:**                                                
       53 +- 분석 결과가 JSON 형식으로 파싱 가능해야 한다                
       54 +- 센티먼트 비율의 합계가 100이어야 한다                       
       55 +- 대표 댓글은 실제 수집된 댓글에서만 인용해야 한다            
       56 +- 분석 중 로딩 상태가 UI에 표시되어야 한다                    
       57 +                                                              
       58 +### 기능 3: 리포트 표시                                       
       59 +분석 결과를 시각적으로 보기 좋은 리포트로 렌더링한다.         
       60 +                                                              
       61 +**리포트 구성 (위→아래 순서):**                               
       62 +1. 전체 요약 텍스트                                           
       63 +2. 센티먼트 비율 가로 바 차트 (긍정=녹색, 중립=회색, 부정=빨강
          +)                                                             
       64 +3. "잘하고 있는 점" 카드 (불릿 리스트)                        
       65 +4. "개선할 점" 카드 (불릿 리스트)                             
       66 +5. "대표 댓글" 섹션 (센티먼트별 그룹)                         
       67 +                                                              
       68 +**수용 기준:**                                                
       69 +- 리포트가 화면에 렌더링되어야 한다                           
       70 +- "다른 영상 분석하기" 버튼으로 초기 상태로 돌아갈 수 있어야  
          +한다                                                          
       71 +                                                              
       72 +### 기능 4: API 키 관리                                       
       73 +사용자가 API 키를 입력하고 브라우저에 저장한다.               
       74 +                                                              
       75 +**동작:**                                                     
       76 +- 앱 최초 진입 시 API 키가 없으면 설정 패널이 자동으로 열린다 
       77 +- API 키는 localStorage에 저장하여 재방문 시 유지한다         
       78 +- 설정 패널은 접었다 펼 수 있다

       81 +                                                              
       82 +**수용 기준:**                                                
       83 +- API 키를 입력하고 저장하면 localStorage에 저장되어야 한다   
       84 +- 페이지를 새로고침해도 키가 유지되어야 한다

      174 +- localStorage 용량: API 키 2개 저장에 ~200바이트. 브라우저 lo

       33 +### ADR-003: 사용자 API 키 직접 입력 방식                     
       34 +**상태**: 확정                                                
       35 +**결정**: YouTube API 키와 Anthropic API 키를 사용자가 UI에서 
          +직접 입력하고, `localStorage`에 저장한다. 서버에는 키를 저장하
          +지 않는다.                                                    
       36 +**배경**: 서버 없이 동작해야 한다는 요구사항. API 키를 서버에 
          +두려면 인증 시스템, DB, 환경 변수 관리가 필요하다.            
       37 +**이유**: 별도 인증/DB가 불필요하다. 사용자가 자신의 API 할당 
          +량을 사용하므로 운영 비용이 0이다. 개인 도구 용도에 적합하다. 
          +키는 per-request로 API Route에 전달되고 서버 메모리에 남지 않 
          +는다.                                                         
       38 +**대안 검토**:                                                
       39 +- `.env` 방식: 로컬에서만 사용 가능. 배포 시 키가 서버에 하드 
          +코딩되어 누구나 사용 가능해짐. 다수 사용자 지원 불가.         
       40 +- OAuth 기반: 사용자 편의성은 높으나 Google OAuth 설정, 토큰  
          +관리, 서버 필요. MVP 범위 초과.                               
       41 +**트레이드오프**: 사용자가 직접 API 키를 발급받아야 하는 진입 
          +장벽이 있다. `localStorage`는 같은 도메인의 JS에서 접근 가능하
          +므로 XSS에 취약하지만, 개인 도구이고 외부 스크립트를 로드하지 
          +않으므로 수용 가능.                                           
       42 +**보안 고려사항**:                                            
       43 +- API 키는 password 타입 입력 필드로 마스킹                   
       44 +- API Route에서 키를 로깅하지 않는다                          
       45 +- 키는 HTTPS 위에서만 전송된다 (개발 환경 제외)

       49 +### ADR-004: 외부 런타임 의존성 제로                          
       50 +**상태**: 확정                                                
       51 +**결정**: Next.js + React 외에 런타임 의존성을 추가하지 않는다
          +. Anthropic SDK, 차트 라이브러리, 상태 관리 라이브러리를 사용 
          +하지 않는다.                                                  
       52 +**배경**: 의존성은 번들 크기, 보안 취약점, 버전 호환성 문제를

       53 +**이유**:                                                     
       54 +- Anthropic API 호출: `fetch` + 헤더 3개 + JSON body. SDK의 자
          +동 재시도, 스트리밍, 타입 생성 등은 MVP에서 불필요.           
       55 +- 센티먼트 차트: CSS flex + percentage width로 구현. chart.js 
          +나 recharts를 추가할 이유 없음.                               
       56 +- 상태 관리: `useState` 6개로 충분. zustand나 jotai를 추가할

       57 +**대안 검토**:                                                
       58 +- `@anthropic-ai/sdk`: 타입 안전성과 자동 재시도 제공. 하지만

       59 +- `recharts`: 센티먼트 바 차트 하나를 위해 ~150KB 추가는 비합 
          +리적.                                                         
       60 +**트레이드오프**: SDK의 타입 안전성, 자동 재시도, 에러 핸들링 
          +유틸리티를 포기한다. 수동으로 타입을 정의하고 에러를 분류해야 
          +한다.

       64 +### ADR-005: 댓글 100개 제한 + 관련도순 정렬                  
       65 +**상태**: 확정                                                
       66 +**결정**: 댓글을 최대 100개까지, `order=relevance` 순으로 수집
          +한다. 페이지네이션으로 추가 수집하지 않는다.                  
       67 +**배경**: YouTube API `commentThreads.list`의 `maxResults` 최 
          +대값은 100이다. 100개 이상을 수집하려면 `nextPageToken`으로 반
          +복 호출해야 한다.                                             
       68 +**이유**:                                                     
       69 +- 100개는 영상의 전반적인 분위기를 파악하기에 충분한 표본이다.
       70 +- 관련도순은 좋아요가 많고 답글이 많은 "의미 있는" 댓글을 우선
          + 가져온다. 최신순보다 대표성이 높다.                          
       71 +- 100개 댓글은 약 10K-30K 토큰으로, Claude Sonnet의 입력 한도(
          +200K) 내에서 여유 있고 비용도 적다.                           
       72 +- API 호출 1회로 끝나므로 YouTube API 할당량 소비가 최소(1 유 
          +닛).                                                          
       73 +**대안 검토**:                                                
       74 +- 500개 수집 (5회 호출): 더 정확한 분석 가능하나, YouTube API 
          +할당량 5배 소비 + Claude 비용 증가 + 응답 시간 증가.          
       75 +- 50개 제한: 비용 절약되지만 표본이 적어 분석 신뢰도 감소.    
       76 +- `order=time` (최신순): 최근 반응을 볼 수 있으나, 스팸이나 단
          +순 댓글이 포함될 확률이 높다.                                 
       77 +**트레이드오프**: 댓글이 1,000개 이상인 영상에서 100개만 분석 
          +하면 전체를 대표하지 못할 수 있다. 하지만 관련도순이므로 가장 
          +영향력 있는 댓글은 포함된다.

       92 +### ADR-007: Claude 프롬프트에서 구조화된 JSON 직접 출력      
       93 +**상태**: 확정                                                
       94 +**결정**: Claude에게 JSON 스키마를 명시하고 "Return ONLY the J

       95 +**배경**: Claude의 응답을 구조화된 데이터로 받는 방법은 두 가

       98 +- Sonnet은 명확한 JSON 스키마 지시를 따르는 데 충분히 신뢰성이

      110 +### ADR-008: API 키를 쿼리 파라미터로 전달 (YouTube Route)    
      111 +**상태**: 확정 (개선 가능)                                    
      112 +**결정**: YouTube API Route에서 API 키를 query parameter(`?api
          +Key=...`)로 받는다. Anthropic API Route에서는 request body로  
          +받는다.                                                       
      113 +**배경**: GET 요청에서 API 키를 전달하는 방법은 query paramete
          +r 또는 custom header이다.                                     
      114 +**이유**: 구현이 가장 단순하다. `URLSearchParams`로 바로 접근 
          +가능. 서비스 레이어에서 URL을 구성하기 쉽다.                  
      115 +**보안 고려사항**:                                            
      116 +- query parameter는 서버 액세스 로그에 기록될 수 있다. 하지만 
          +Next.js 개발 서버와 Vercel은 기본적으로 query parameter를 로깅
          +하지 않는다.                                                  
      117 +- HTTPS 위에서 전송되므로 네트워크 상에서는 암호화된다.       
      118 +- 프로덕션 배포 시 보안을 강화하려면 custom header(`x-youtube-
          +api-key`)로 전환할 수 있다. 코드 변경량은 적다.               
      119 +**트레이드오프**: 서버 로그에 키가 남을 가능성. 개인 도구이므 
          +로 수용 가능.
