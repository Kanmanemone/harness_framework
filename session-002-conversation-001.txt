     Harness 프레임워크 세팅 개선 플랜

     Context

     현재 하네스 프레임워크는 executor(execute.py)와 워크플로우
     문서(harness.md)는 잘 갖춰져 있으나, 실제 사용 시 여러 문제가
     발생한다. Stop hook이 매 세션마다 실패하고, Windows 환경에서 인코딩
     크래시가 나며, executor와 Claude 세션이 이중 커밋을 만들고, 위험 명령
     차단이 불완전하다. 이 플랜은 실제로 하네스를 돌렸을 때 깨지는 것들을
     우선 수정한다.

     ---
     변경 1: Stop hook 조건부 실행으로 수정

     문제: settings.json의 Stop hook이 npm run lint && npm run build && npm
      run test를 실행하지만 package.json이 없어서 매 세션 종료 시 반드시
     실패한다.

     파일: .claude/settings.json

     변경: package.json 존재 여부를 체크한 뒤 실행하도록 수정
     "command": "if [ -f package.json ]; then npm run lint 2>&1 && npm run
     build 2>&1 && npm run test 2>&1; else echo 'package.json 없음 — skip';
      fi"

     ---
     변경 2: execute.py Windows 인코딩 크래시 수정

     문제: _load_guardrails()에서 read_text()를 encoding 없이 호출. Windows
      기본 인코딩(cp949)으로 한글 문서를 읽다 UnicodeDecodeError 발생.

     파일: scripts/execute.py

     변경: _load_guardrails() (177-186행)에서 read_text(encoding="utf-8")
     명시
     sections.append(f"## 프로젝트 규칙 
     (CLAUDE.md)\n\n{claude_md.read_text(encoding='utf-8')}")
     # ...
     sections.append(f"## {doc.stem}\n\n{doc.read_text(encoding='utf-8')}")

     _invoke_claude()의 step_file.read_text() (237행)도 동일하게 수정.

     테스트: test_execute.py의 관련 테스트가 이미 tempfile을 쓰므로 추가
     수정 불필요.

     ---
     변경 3: 이중 커밋 문제 해결 — preamble에서 커밋 지시 제거

     문제: _build_preamble() 규칙 6이 Claude에게 "모든 변경사항을
     커밋하라"고 지시하는데, _commit_step()이 이미 자동으로 커밋한다.
     결과적으로 Claude가 커밋 → executor가 또 커밋하여 이중/빈 커밋 발생.

     파일: scripts/execute.py (199-225행)

     변경: 규칙 6의 커밋 지시를 "커밋하지 마라. executor가 자동 커밋한다"로
      변경

     커밋한다.\n\n---\n\n"

     테스트: test_execute.py의 TestBuildPreamble에서 preamble 내용 검증
     업데이트 필요.

     변경 4: PreToolUse 위험 명령 패턴 보강

     문제: 현재 패턴이 rm -rf, git push --force, git reset --hard, DROP 
     TABLE 4가지만 차단. git checkout ., git clean -fd, git stash drop 등
     파괴적 명령이 빠져 있다.

     파일: .claude/settings.json

     변경: grep 패턴을 확장

     ckout\s+\.|git\s+clean\s+-[fd]|git\s+stash\s+drop|DROP\s+TABLE'

     변경 7: Claude 호출 타임아웃을 CLI 인자로 설정 가능하게

     30분으로 부족할 수 있고, 단순 step에서 Claude가 멈추면 30분을
     낭비한다.

     파일: scripts/execute.py

     변경:

     - _invoke_claude()에서 self._default_timeout 사용
     - step별 "timeout" 필드도 지원: step.get("timeout", 
     self._default_timeout)

     테스트: test_execute.py에 커스텀 타임아웃 테스트 추가.

     문제: reversed(index["steps"])로 뒤에서부터 순회하면서 status != 
     "pending"이면 break. 만약 뒤쪽 step이 completed인데 앞쪽에 error가
