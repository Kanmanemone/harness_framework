# Architecture Decision Records

## 철학
MVP 속도 최우선. 외부 의존성 최소화. 작동하는 최소 구현을 선택한다. 개인 도구 수준의 앱이므로 과도한 엔지니어링을 피한다.

---

### ADR-001: Next.js App Router 선택
**결정**: Next.js 15 (App Router)를 프레임워크로 사용한다.
**이유**: Anthropic API는 브라우저에서 직접 호출할 수 없다 (CORS 제한). Next.js API Route를 프록시로 활용하면 별도 백엔드 서버 없이 이 문제를 해결할 수 있다. React 생태계 활용 및 빌드/배포 편의성도 장점.
**트레이드오프**: 서버 기능을 거의 쓰지 않으므로 Vite + React 대비 번들 크기가 약간 크다. API Route 2개만 사용하므로 수용 가능한 수준.

### ADR-002: Claude Sonnet 모델 사용
**결정**: 센티먼트 분석에 `claude-sonnet-4-20250514` 모델을 사용한다.
**이유**: 댓글 분석은 복잡한 추론이 아닌 분류+요약 태스크다. Sonnet은 이 수준의 작업에 충분한 성능을 제공하면서 Opus 대비 비용이 훨씬 낮다. 100개 댓글 분석 시 응답 시간도 짧다.
**트레이드오프**: 매우 미묘한 맥락 분석이 필요한 경우 Opus가 나을 수 있으나, MVP에서는 Sonnet으로 충분하다.

### ADR-003: 사용자 API 키 직접 입력 방식
**결정**: YouTube API 키와 Anthropic API 키를 사용자가 UI에서 직접 입력하고, localStorage에 저장한다.
**이유**: 서버에 키를 저장하지 않으므로 별도 인증/DB가 불필요하다. 사용자가 자신의 API 할당량을 사용하므로 운영 비용이 0이다. 개인 도구 용도에 적합하다.
**트레이드오프**: 사용자가 직접 API 키를 발급받아야 하는 진입 장벽이 있다. localStorage는 XSS에 취약할 수 있으나, 개인 도구이므로 수용 가능.

### ADR-004: 외부 런타임 의존성 제로
**결정**: Next.js + React 외에 런타임 의존성을 추가하지 않는다. Anthropic SDK, 차트 라이브러리, 상태 관리 라이브러리를 사용하지 않는다.
**이유**: Anthropic API는 단순 fetch 호출로 충분하다 (헤더 3개 + JSON body). 센티먼트 차트는 CSS flex로 구현 가능하다. 앱 상태는 useState 몇 개로 관리 가능하다. 의존성이 적을수록 유지보수가 쉽다.
**트레이드오프**: SDK가 제공하는 타입 안전성, 자동 재시도, 스트리밍 등의 편의 기능을 포기한다. MVP 범위에서는 이런 기능이 불필요하다.
