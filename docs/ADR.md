# Architecture Decision Records

## 철학
MVP 속도 최우선. 외부 의존성 최소화. 작동하는 최소 구현을 선택한다. 개인 도구 수준의 앱이므로 과도한 엔지니어링을 피한다. 모든 결정은 "이것 없이도 MVP가 동작하는가?"를 기준으로 판단한다.

---

### ADR-001: Next.js App Router 선택
**상태**: 확정
**결정**: Next.js 15 (App Router)를 프레임워크로 사용한다.
**배경**: Anthropic API는 브라우저에서 직접 호출할 수 없다 (`Access-Control-Allow-Origin` 헤더가 없음). YouTube Data API는 브라우저에서 호출 가능하지만, API 키가 네트워크 탭에 노출된다.
**이유**: Next.js API Route를 프록시로 활용하면 별도 백엔드 서버 없이 CORS 문제를 해결할 수 있다. 두 API 호출을 서버 사이드에서 처리하여 키 노출 리스크를 줄인다. React 생태계 활용 및 Vercel 배포 편의성도 장점.
**대안 검토**:
- Vite + React: CORS 해결 불가. 별도 프록시 서버가 필요해짐.
- HTML + Vanilla JS: 같은 CORS 문제. 추가로 컴포넌트 재사용, 상태 관리가 번거로움.
**트레이드오프**: 서버 기능을 API Route 2개만 사용하므로 Vite 대비 번들 크기가 약간 크다. Next.js의 SSR, ISR, 미들웨어 등 대부분의 기능을 사용하지 않는다.

### ADR-002: Claude Sonnet 모델 사용
**상태**: 확정
**결정**: 센티먼트 분석에 `claude-sonnet-4-20250514` 모델을 사용한다.
**배경**: 댓글 분석은 분류(긍정/중립/부정) + 요약(강점/개선점) + 선택(대표 댓글) 태스크다. 고도의 추론이 필요하지 않다.
**이유**: Sonnet은 이 수준의 작업에 충분한 성능을 제공하면서 Opus 대비 비용이 낮다. 100개 댓글(~10K-30K 토큰 입력)에 대한 응답이 빠르다.
**대안 검토**:
- Claude Opus: 더 높은 분석 품질이 가능하나, 비용이 높고 응답이 느리다. 댓글 분석에는 과도.
- Claude Haiku: 더 빠르고 저렴하나, 구조화된 JSON 출력의 신뢰성이 Sonnet보다 낮을 수 있다.
- 외부 센티먼트 API (Google NLP 등): 긍정/부정 분류만 가능하고, "강점/개선점 정리"나 "댓글 언어 대응" 같은 유연한 분석이 불가능.
**트레이드오프**: Opus 대비 미묘한 맥락(비꼬기, 이중 의미 등) 해석이 약할 수 있으나, MVP에서 수용 가능. 모델 변경은 `constants.ts`의 상수 하나만 바꾸면 되므로 전환 비용이 낮다.

### ADR-003: 사용자 API 키 직접 입력 방식
**상태**: 확정
**결정**: YouTube API 키와 Anthropic API 키를 사용자가 UI에서 직접 입력하고, `localStorage`에 저장한다. 서버에는 키를 저장하지 않는다.
**배경**: 서버 없이 동작해야 한다는 요구사항. API 키를 서버에 두려면 인증 시스템, DB, 환경 변수 관리가 필요하다.
**이유**: 별도 인증/DB가 불필요하다. 사용자가 자신의 API 할당량을 사용하므로 운영 비용이 0이다. 개인 도구 용도에 적합하다. 키는 per-request로 API Route에 전달되고 서버 메모리에 남지 않는다.
**대안 검토**:
- `.env` 방식: 로컬에서만 사용 가능. 배포 시 키가 서버에 하드코딩되어 누구나 사용 가능해짐. 다수 사용자 지원 불가.
- OAuth 기반: 사용자 편의성은 높으나 Google OAuth 설정, 토큰 관리, 서버 필요. MVP 범위 초과.
**트레이드오프**: 사용자가 직접 API 키를 발급받아야 하는 진입 장벽이 있다. `localStorage`는 같은 도메인의 JS에서 접근 가능하므로 XSS에 취약하지만, 개인 도구이고 외부 스크립트를 로드하지 않으므로 수용 가능.
**보안 고려사항**:
- API 키는 password 타입 입력 필드로 마스킹
- API Route에서 키를 로깅하지 않는다
- 키는 HTTPS 위에서만 전송된다 (개발 환경 제외)

### ADR-004: 외부 런타임 의존성 제로
**상태**: 확정
**결정**: Next.js + React 외에 런타임 의존성을 추가하지 않는다. Anthropic SDK, 차트 라이브러리, 상태 관리 라이브러리를 사용하지 않는다.
**배경**: 의존성은 번들 크기, 보안 취약점, 버전 호환성 문제를 가져온다. 이 앱의 기능은 모두 기본 Web API로 구현 가능하다.
**이유**:
- Anthropic API 호출: `fetch` + 헤더 3개 + JSON body. SDK의 자동 재시도, 스트리밍, 타입 생성 등은 MVP에서 불필요.
- 센티먼트 차트: CSS flex + percentage width로 구현. chart.js나 recharts를 추가할 이유 없음.
- 상태 관리: `useState` 6개로 충분. zustand나 jotai를 추가할 이유 없음.
**대안 검토**:
- `@anthropic-ai/sdk`: 타입 안전성과 자동 재시도 제공. 하지만 API 호출 1개에 SDK 전체를 번들에 포함하는 것은 과도.
- `recharts`: 센티먼트 바 차트 하나를 위해 ~150KB 추가는 비합리적.
**트레이드오프**: SDK의 타입 안전성, 자동 재시도, 에러 핸들링 유틸리티를 포기한다. 수동으로 타입을 정의하고 에러를 분류해야 한다.

### ADR-005: 댓글 100개 제한 + 관련도순 정렬
**상태**: 확정
**결정**: 댓글을 최대 100개까지, `order=relevance` 순으로 수집한다. 페이지네이션으로 추가 수집하지 않는다.
**배경**: YouTube API `commentThreads.list`의 `maxResults` 최대값은 100이다. 100개 이상을 수집하려면 `nextPageToken`으로 반복 호출해야 한다.
**이유**:
- 100개는 영상의 전반적인 분위기를 파악하기에 충분한 표본이다.
- 관련도순은 좋아요가 많고 답글이 많은 "의미 있는" 댓글을 우선 가져온다. 최신순보다 대표성이 높다.
- 100개 댓글은 약 10K-30K 토큰으로, Claude Sonnet의 입력 한도(200K) 내에서 여유 있고 비용도 적다.
- API 호출 1회로 끝나므로 YouTube API 할당량 소비가 최소(1 유닛).
**대안 검토**:
- 500개 수집 (5회 호출): 더 정확한 분석 가능하나, YouTube API 할당량 5배 소비 + Claude 비용 증가 + 응답 시간 증가.
- 50개 제한: 비용 절약되지만 표본이 적어 분석 신뢰도 감소.
- `order=time` (최신순): 최근 반응을 볼 수 있으나, 스팸이나 단순 댓글이 포함될 확률이 높다.
**트레이드오프**: 댓글이 1,000개 이상인 영상에서 100개만 분석하면 전체를 대표하지 못할 수 있다. 하지만 관련도순이므로 가장 영향력 있는 댓글은 포함된다.

### ADR-006: 다크모드 고정 + 단일 페이지 설계
**상태**: 확정
**결정**: 다크모드만 지원하고 라이트모드 토글은 제공하지 않는다. 앱 전체를 단일 페이지에서 상태 전환으로 구현한다.
**배경**: 이 앱은 개인 분석 도구이다. 다수 사용자의 접근성보다 개발 속도와 일관된 디자인을 우선한다.
**이유**:
- 다크모드 고정: 테마 전환 로직(CSS 변수, 시스템 설정 감지, 토글 UI) 불필요. 디자인 작업량 절반.
- 단일 페이지: URL 입력 → 로딩 → 리포트가 하나의 흐름이므로 라우팅 불필요. `useState`로 phase를 관리하는 것이 가장 단순.
**트레이드오프**: 라이트모드 선호 사용자에게 불편할 수 있다. 리포트 URL 공유(딥 링크)가 불가능하다. 하지만 MVP에서 히스토리 기능이 없으므로 딥 링크의 의미가 없다.

### ADR-007: Claude 프롬프트에서 구조화된 JSON 직접 출력
**상태**: 확정
**결정**: Claude에게 JSON 스키마를 명시하고 "Return ONLY the JSON object, nothing else"를 지시하여 응답 전체를 JSON으로 받는다. `tool_use`(function calling)를 사용하지 않는다.
**배경**: Claude의 응답을 구조화된 데이터로 받는 방법은 두 가지: (1) 프롬프트에서 JSON 출력 지시, (2) `tool_use` 기능으로 스키마 강제.
**이유**:
- 프롬프트 방식이 구현이 단순하다. API 요청 body에 `tools` 배열을 추가하지 않아도 된다.
- Sonnet은 명확한 JSON 스키마 지시를 따르는 데 충분히 신뢰성이 있다.
- 응답 파싱이 `JSON.parse` 한 줄로 끝난다.
**방어 코드**:
- Claude가 ` ```json ``` `으로 감쌀 경우를 대비하여 코드 펜스를 제거하는 전처리 추가.
- 응답에서 첫 `{`부터 마지막 `}`까지 추출하는 fallback 로직.
- `sentiment` 합계가 100이 아닌 경우 클라이언트에서 정규화.
**대안 검토**:
- `tool_use`: 스키마 준수가 보장되지만 API 요청이 복잡해지고, tool_use 응답 파싱 로직이 추가된다. 이 앱의 스키마는 단순하므로 과도.
**트레이드오프**: JSON 출력이 깨질 가능성이 낮지만 0은 아니다. 방어 코드로 대부분의 케이스를 커버하고, 그래도 실패하면 사용자에게 재시도를 안내한다.

### ADR-008: API 키를 쿼리 파라미터로 전달 (YouTube Route)
**상태**: 확정 (개선 가능)
**결정**: YouTube API Route에서 API 키를 query parameter(`?apiKey=...`)로 받는다. Anthropic API Route에서는 request body로 받는다.
**배경**: GET 요청에서 API 키를 전달하는 방법은 query parameter 또는 custom header이다.
**이유**: 구현이 가장 단순하다. `URLSearchParams`로 바로 접근 가능. 서비스 레이어에서 URL을 구성하기 쉽다.
**보안 고려사항**:
- query parameter는 서버 액세스 로그에 기록될 수 있다. 하지만 Next.js 개발 서버와 Vercel은 기본적으로 query parameter를 로깅하지 않는다.
- HTTPS 위에서 전송되므로 네트워크 상에서는 암호화된다.
- 프로덕션 배포 시 보안을 강화하려면 custom header(`x-youtube-api-key`)로 전환할 수 있다. 코드 변경량은 적다.
**트레이드오프**: 서버 로그에 키가 남을 가능성. 개인 도구이므로 수용 가능.

### ADR-009: UI 언어 한국어 고정
**상태**: 확정
**결정**: 앱의 UI 텍스트(버튼, 에러 메시지, 안내 문구 등)는 한국어로 고정한다. i18n 시스템을 도입하지 않는다.
**배경**: 분석 결과는 Claude가 댓글 언어에 맞춰 자동으로 해당 언어로 출력한다. 별도 처리 없이도 다국어 분석이 가능하다. 문제는 UI 텍스트(버튼, 라벨, 에러 메시지)의 언어이다.
**이유**: 주 사용자가 한국어 사용자이다. i18n 라이브러리(next-intl 등)를 도입하면 모든 문자열을 키-값으로 관리해야 하고, 번역 파일 유지보수 부담이 생긴다. MVP에서 해외 사용자 대응은 범위 밖이다.
**트레이드오프**: 한국어를 모르는 사용자는 UI를 사용하기 어렵다. 하지만 분석 결과 자체는 댓글 언어에 맞춰 출력되므로 핵심 가치는 유지된다.

### ADR-010: 분석 중 취소 기능 미제공
**상태**: 확정
**결정**: 분석이 시작되면 사용자가 중간에 취소할 수 없다. 완료 또는 에러까지 대기한다.
**배경**: 사용자가 로딩 중 실수를 알아차리거나 마음이 바뀔 수 있다. 취소 기능이 있으면 UX가 개선된다.
**이유**:
- 취소를 구현하려면 `AbortController`를 클라이언트에서 관리하고, API Route에서도 전달된 요청을 abort해야 한다. Next.js API Route에서 클라이언트 disconnect를 감지하는 것은 추가 복잡도가 있다.
- 분석 전체 소요 시간은 10-20초 수준이다. YouTube API 호출(~3초)은 빠르게 끝나고, Claude 응답(~5-15초)이 대부분이다.
- 취소해도 Claude API 호출은 이미 발생했으므로 비용은 동일하다.
**트레이드오프**: 사용자가 잘못된 URL을 넣고 분석을 시작했을 때, 10-20초를 기다려야 한다. 에러가 발생하면 URL이 유지되므로 수정 후 재시도는 쉽다.

### ADR-011: 에러 시 사용자 입력 보존
**상태**: 확정
**결정**: 에러가 발생하면 URL 입력 필드의 값을 유지한다. 사용자가 다시 입력하지 않아도 되도록 한다.
**배경**: 에러 발생 시 사용자 경험의 가장 큰 불만은 "입력했던 내용이 사라지는 것"이다. 특히 긴 URL을 복사해서 붙여넣었을 때 다시 찾아야 하는 상황은 답답하다.
**이유**: URL 값은 React 상태(`useState`)에 있으므로 phase가 바뀌어도 자연스럽게 유지된다. 추가 코드가 거의 필요 없다. "다시 시도" 버튼을 누르면 동일 URL로 바로 재분석할 수 있다.
**적용 범위**:
- `error → idle` (다시 시도): URL 유지
- `error → idle` (다른 영상 분석하기): URL 비움
- `report → idle` (다른 영상 분석하기): URL 비움
- `report → loading` (분석 버튼 재클릭): URL 유지 (같은 영상 재분석)

### ADR-012: API 키 관련 에러 시 설정 패널 자동 열기
**상태**: 확정
**결정**: YouTube/Anthropic API 키가 잘못되어 에러가 발생하면, 에러 메시지를 표시하면서 설정 패널을 자동으로 열어 사용자가 키를 수정할 수 있도록 한다.
**배경**: API 키 오류는 사용자가 가장 혼란스러워하는 에러 유형이다. "키가 잘못되었습니다"라고만 알려주면 사용자는 설정 패널을 직접 찾아서 열어야 한다.
**이유**: 에러 원인과 해결 동선을 최소화한다. 에러 메시지를 보는 즉시 키 입력 필드가 보이므로 다음 행동이 명확하다.
**구분 기준**: API Route에서 `isApiKeyError: true` 플래그를 에러 응답에 포함한다. 클라이언트에서 이 플래그를 확인하여 설정 패널을 연다. 할당량 초과, 서버 오류 등 키와 무관한 에러에서는 패널을 열지 않는다.
