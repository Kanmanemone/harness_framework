   결과를 확인할 수 있어야 한다는 거야. 아주 간단하게 만들 예정이며, 로그인 
   기능이나 서버는 넣지 않을 거야.                                          

● 좋은 아이디어입니다. 핵심 요구사항을 정리하고 몇 가지 기술적 결정이 필요한
  부분을 짚어보겠습니다.

  요구사항 정리

  - YouTube URL 입력 → 댓글 수집 → 센티먼트 분석 → 리포트 출력
  - 로그인 없음, 서버 없음 (클라이언트 사이드 앱)
  - 최대한 심플하게

  기술적으로 결정해야 할 사항

  1. 댓글 수집: YouTube Data API v3를 사용해야 합니다. API 키가 필요한데, 서버가
   없으므로 클라이언트에서 직접 호출하게 됩니다. (개인 사용/프로토타입
  수준이라면 괜찮지만, 배포 시 API 키 노출 리스크가 있습니다.)

  2. 센티먼트 분석: 댓글을 분석할 엔진이 필요합니다. Claude API를 사용하면 단순
  긍/부정을 넘어서 "개선할 점", "잘하고 있는 점"까지 자연어로 정리해줄 수
  있습니다.

  3. API 키 관리: 서버 없이 진행하려면, 사용자가 직접 자신의 YouTube API 키와
  Claude API 키를 입력하는 방식이 가장 현실적입니다.

       8 +### ADR-001: Next.js App Router 선택                           
       9 +**결정**: Next.js 15 (App Router)를 프레임워크로 사용한다.     
      10 +**이유**: Anthropic API는 브라우저에서 직접 호출할 수 없다 (COR
         +S 제한). Next.js API Route를 프록시로 활용하면 별도 백엔드 서버
         + 없이 이 문제를 해결할 수 있다. React 생태계 활용 및 빌드/배포 
         +편의성도 장점.                                                 
      11 +**트레이드오프**: 서버 기능을 거의 쓰지 않으므로 Vite + React  
         +대비 번들 크기가 약간 크다. API Route 2개만 사용하므로 수용 가 
         +능한 수준.                                                     
      12 +                                                               
      13 +### ADR-002: Claude Sonnet 모델 사용                           
      14 +**결정**: 센티먼트 분석에 `claude-sonnet-4-20250514` 모델을 사 
         +용한다.                                                        
      15 +**이유**: 댓글 분석은 복잡한 추론이 아닌 분류+요약 태스크다. So
         +nnet은 이 수준의 작업에 충분한 성능을 제공하면서 Opus 대비 비용
         +이 훨씬 낮다. 100개 댓글 분석 시 응답 시간도 짧다.             
      16 +**트레이드오프**: 매우 미묘한 맥락 분석이 필요한 경우 Opus가 나
         +을 수 있으나, MVP에서는 Sonnet으로 충분하다.                   
      17 +                                                               
      18 +### ADR-003: 사용자 API 키 직접 입력 방식                      
      19 +**결정**: YouTube API 키와 Anthropic API 키를 사용자가 UI에서  
         +직접 입력하고, localStorage에 저장한다.                        
      20 +**이유**: 서버에 키를 저장하지 않으므로 별도 인증/DB가 불필요하
         +다. 사용자가 자신의 API 할당량을 사용하므로 운영 비용이 0이다. 
         +개인 도구 용도에 적합하다.                                     
      21 +**트레이드오프**: 사용자가 직접 API 키를 발급받아야 하는 진입  
         +장벽이 있다. localStorage는 XSS에 취약할 수 있으나, 개인 도구이
         +므로 수용 가능.                                                
      22 +                                                               
      23 +### ADR-004: 외부 런타임 의존성 제로                           
      24 +**결정**: Next.js + React 외에 런타임 의존성을 추가하지 않는다.
         + Anthropic SDK, 차트 라이브러리, 상태 관리 라이브러리를 사용하 
         +지 않는다.                                                     
      25 +**이유**: Anthropic API는 단순 fetch 호출로 충분하다 (헤더 3개

         +는 useState 몇 개로 관리 가능하다. 의존성이 적을수록 유지보수가
         + 쉽다.                                                         
      26 +**트레이드오프**: SDK가 제공하는 타입 안전성, 자동 재시도, 스트
         +리밍 등의 편의 기능을 포기한다. MVP 범위에서는 이런 기능이 불필
         +요하다.
